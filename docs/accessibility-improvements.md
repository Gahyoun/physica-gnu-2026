# 가시성과 접근성 개선

2026-11-02. GNU·KRDS 테마의 청색·회색·흰 바탕, 원본 로고, 정보 안내형 배치를 유지하면서 탐색 요소를 읽고 조작하기 쉽게 보완했다. 학습 내용과 물리 모형을 바꾸는 작업은 아니다.

## 적용한 내용

- 원저자·쪽수·중분류·푸터 같은 보조 정보는 화면에서 14px를 기준으로 읽을 수 있게 조정했다. 44×44px 이상의 조작 영역은 이번 구현의 터치 기준으로 사용한다.
- 입력·보조 버튼의 경계에는 밝은 화면 `#717B84`, 어두운 화면 `#8C9AA6`을 사용한다. 옅은 문서 구분선과 조작 요소의 경계를 구분하며 대학 로고의 색은 유지한다.
- 본문·목차·자료 링크에 밑줄을 더하고, 선택 상태는 굵기·밑줄·경계도 함께 사용해 색만으로 판단하지 않게 한다.
- 키보드 포커스는 배경과 구분되는 두 겹 표시로 보완한다. 본문 바로가기와 기본 HTML 펼침 요소, 검색·모바일 목차의 Esc 닫기와 포커스 복원을 유지한다.
- 모바일 목차의 중분류는 말줄임 대신 자연스럽게 줄바꿈한다. 검색 메뉴가 펼쳐진 상태에서도 320px 화면 밖으로 밀리지 않게 조정한다.
- 목차의 566개 쪽 이동 링크에는 주제명과 쪽수를 포함한 접근 가능한 이름을 제공한다. 화면의 짧은 `1p` 표기는 유지한다.

스타일 보완은 `assets/site-layout.css`, 탐색 동작과 이름은 공통 탐색 코드·목차 생성 원본에서 관리한다. 생성 HTML을 직접 고치는 대신 원본을 수정하고 다시 빌드한다.

## 확인 기준

일반 글자에는 배경 대비 4.5:1을 기준으로 삼고, 원본 로고를 대비 확보용 색으로 다시 칠하지 않는다. [W3C WCAG 2.2 글자 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참고했다.

입력 경계와 상태를 식별하는 시각 정보는 인접 색과 3:1 이상 구분되도록 살핀다. 모든 장식 선이나 버튼 테두리에 같은 기준이 일괄 적용되는 것은 아니므로, 실제 조작 요소를 식별하는 정보인지 구분한다. [W3C 비텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)을 따른다.

좁은 화면에서는 일반 내용을 세로로 읽을 수 있게 하고 메뉴를 연 상태도 확인한다. 긴 수식·도표처럼 자체 가로 이동이 필요한 부분은 페이지 전체의 가로 넘침과 구분한다. [W3C 재배치 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)을 참고했다.

사용자가 행간·문단 간격·자간·단어 간격을 늘려도 글자와 기능이 잘리지 않는지 점검한다. 이 수치를 기본 디자인에 강제하는 대신 사용자 설정에 견디도록 한다. [W3C 텍스트 간격 설명](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)을 참고했다.

## 재검증과 기록

이번 변경은 대비·글자 크기·조작 영역·포커스·메뉴·확대·텍스트 간격에 대한 범위를 확인한다. 실제 실행 결과와 날짜는 아래 보고서에서 확인한다. 밝음·어두움 각각 320/390/768/1440px를 포함한 집중 검사 12항목, 탐색 배치 12항목, 수식 화면 1,713건, 기존 브라우저 상호작용 135건이 통과했다. 단위검사는 680개와 수식 보고서 의존성 검사 3개를 나누어 실행해 총 683개가 통과했다. 확대 검사는 CSS 200%·400% 확대와 320px 뷰포트 재배치이며 브라우저 자체 확대 기능의 수동 평가는 포함하지 않는다.

| 기록 | 확인 범위 |
|---|---|
| [접근성 확인](accessibility-report.json) | 렌더링된 대비·크기·키보드·좁은 화면·사용자 텍스트 설정 |
| [탐색 배치 확인](navigation-layout-report.json) | 홈 목차·검색·모바일 탐색·테마·인쇄 |
| [수식 화면 확인](math-ui-report.json) | 변경된 스타일을 적용한 수식 포함 페이지와 의존성 해시 |
| [종합 브라우저 확인](browser-report.json) | 기존 교재·탐색·검색·상호작용의 회귀 확인 |

과거 보고서는 당시 구현에 대한 근거다. 이번 재검증 여부는 해당 보고서의 실행 날짜·검사 범위·소스 해시로 구분한다. 특정 항목의 자동·브라우저 검사 결과를 전체 WCAG 적합성 인증이나 스크린리더 사용자 평가 완료로 해석하지 않는다.

Playwright와 Chrome이 설치된 개발 환경에서 로컬 서버를 먼저 실행한다. `PHYSICA_PLAYWRIGHT`는 프로젝트 밖에 설치한 Playwright 모듈 경로를 사용할 때만 지정한다.

```sh
node tools/build.mjs
python3 -m http.server 8775 --bind 127.0.0.1
# 별도 터미널
PHYSICA_BASE_URL=http://127.0.0.1:8775/ PHYSICA_BROWSER_CHANNEL=chrome PHYSICA_ACCESSIBILITY_REPORT=docs/accessibility-report.json node tools/accessibility-check.mjs
```
