# 광학 리마스터 20개 — 50개 병렬 묶음 01

## 구현 범위

원본마다 개별 MainTimeline 계산·조작을 이식했으며, 9개 서로 다른 RayTracer 버전을 원본 소스 해시로 구분해 보존한다. 20개의 굴절면·얇은 렌즈·두꺼운 렌즈·렌즈 조합·구면/타원/포물면 거울·신기루·프레넬 렌즈를 새 SVG 도형과 HTML 조작으로 렌더링한다. 원본 그림, 프레임 캡처, 비트맵, Ruffle 플레이어는 리마스터 화면에 사용하지 않는다.

광선과 파면은 동일한 광학 거리 계산에서 진행한다. 원본의 광원 위치, 초점/상 위치 표시, 반사·굴절·전반사, 원본 버튼과 체크박스 및 슬라이더 범위를 유지한다. 선은 경상국립대 파랑과 회색을 사용하고 광선·파면 선의 opacity는 0.65이다. 타임라인은 그림 아래에 두며 화면 밖과 숨겨진 탭에서는 계산을 멈춘다. 원본 저작자와 원본 재생 링크는 교재의 공통 카드가 제공한다.

## 최종 결과

20개 모두 통과했다. 원본 소스 수치 1,553,380회 비교, 실제 HTML UI 60개 케이스·1,047개 체크, 물리 단위검증 33개, 실제 원본 AS3 재생 수치 97276회 비교를 완료했다. 실제 원본 광선 좌표의 최대 차이는 1e-7 허용오차 이내였으며 `originalRuntimeVerified`는 true이다. 원본 Timer가 멈춘 뒤 추가 콜백 후보 상태를 사용한 관측은 0개였다.

## 검증 구분

- `optics-batch50-source-report.json`: 원본 AS3 메서드를 별도의 동적 멤버 스코프 참조 실행기로 해석하고, 배포하는 명시적 JS 멤버 계산과 비교한다. 기본값, 각 슬라이더의 최소·기본·중간·최대 독립 입력, 각 체크박스, 각 원본 버튼, 두 광원 드래그 위치에서 100개 광학 계산 단계를 검사한다. 계산 비교는 실제 원본 런타임 관측과 구분한다.
- `optics-batch50-ui-report.json`: 실제 HTML 리마스터에서 320·768·1360 px, 총 60개 케이스를 검사한다. 재생 중 광선 변화, 일시정지, 단계 탐색, 슬라이더·체크박스·원본 버튼·키보드 광원 이동·초기화, SVG 표시, 0.65 선 투명도, 가로 넘침을 검사한다.
- `optics-batch50-runtime-report.json`: 실제 Ruffle AVM2에서 원본을 재생한다. 새 빈 observer만 삽입하고 기존 ABC·문서 클래스·태그·프레임 헤더·원본 Timer는 바이트 단위로 유지한다. 공개 광학 장치 값과 모든 광선의 위치·방향·존재하는 반사/굴절 횟수를 읽기만 한다. 원본 함수 호출, Timer 강제 진행, 원본 조작값 강제 변경은 하지 않는다.
- `tools/optics-batch50-physics.test.mjs`: 33개 단위검증. 각 커널의 같은 광학 거리 진행, 평면 경계의 스넬 법칙과 전반사, 렌즈 초점 극한 및 20개 장치의 유한 수치를 검사한다.

실제 런타임 비교는 자연스럽게 진행되는 기본/원본 무작위 장치 조건을 대상으로 한다. 원본의 공개 장치 설정을 읽어 같은 설정의 독립 HTML 모델을 만들고 전체 광선 배열에서 대응하는 광학 단계와 수치를 검사한다. 원본 이벤트 처리 상태의 수치 일치를 검증하며, 브라우저와 Flash의 벽시계 예약 시간까지 같다는 주장은 하지 않는다. 연속값의 모든 조합과 무한한 입력 이력은 검사하지 않았다. 보고서의 `fullEquivalence`는 false이다.

## 확인한 원본 차이와 교정

`toy_Lens.swf`는 원본의 1픽셀 그림 테두리 때문에 광선 경계가 SWF 선언 크기와 다르다. 실제 AS3 공개 `indexField.boundRect`는 x=-310, y=-131, width=701, height=251이었다. 선언 크기 700×250을 그대로 쓰면 경계 가까운 두 광선이 한 단계 일찍 멈췄다. 이 수치 경계를 해당 파일에만 반영했으며 새 SVG 그림과 계산을 사용한다.

원본 `focalLength()`의 근축 식과 실제 광선/상 위치 계산은 별도로 유지한다. 두꺼운 렌즈에서 원본이 사용하는 각 방식의 차이를 임의의 단일 일반식으로 대체하지 않는다. 원본에서 새로운 장치 조건을 무작위로 만드는 버튼도 유지한다.

원본은 내부 광선의 비율이 10% 아래로 내려가면 최대 계산 단계 전에도 종료한다. 따라서 모든 광선이 경계 밖인지를 검사하는 것만으로는 재시작 여부를 판단할 수 없다. 리마스터는 자연 완료와 사용자의 일시정지를 구분하고, 자연 완료 또는 끝으로 탐색한 뒤 재생하면 파면을 초기화해 다시 진행한다. 20개 전부에 대해 세 화면 크기에서 끝 탐색 후 재생을 추가 검사한다.

## 파일 구성

`src/native-optics-batch50-rays.json`은 정확한 20개 ID·개별 원본 소스 해시·조작 범위·프로그램/커널 모듈과 광선 경계를 기록한다. `src/native-optics-batch50-placements.json`은 원본 저작자가 배치한 이름 있는 마커/버튼의 숫자 좌표만 보존하며 그림을 포함하지 않는다. `tools/optics-batch50-capture.py`는 이식 산출물을 재현하고, 원본 추출 소스는 공개 파일에서 제외된 `preview/private-scripts`에서만 읽는다.

광학 담당 최초 96개 중 이전 15개와 이번 20개를 합쳐 35개를 구현했으며, 이 담당 목록에서 남은 항목은 61개이다. 이전 Jones/액정 묶음의 AS3 실제 관측 미완료 여부는 이전 보고서의 별도 범위이며, 이번 20개 결과로 대신 완료 처리하지 않는다.
