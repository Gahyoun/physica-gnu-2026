## 계산과 표시

4개의 전위 계산은 별도 worker에서 수행한다. 순차 갱신을 Jacobi 동시 갱신이나 다른 해석식으로 바꾸지 않는다. 뒤로 탐색하면 기준 장에서 원본 순서로 다시 계산한다. 경계 이벤트는 현재 장에 적용하며 초기 상태 버튼만 처음 장으로 돌아간다. 표시 전용 iso/단면/평면/관측 구역은 물리 장을 초기화하지 않는다. 입력 이벤트를 짧게 모아 계산하고 재생 중에는 대기 중인 계산 목표를 최신값으로 합친다. 보이지 않는 카드와 숨겨진 탭은 재생을 멈춘다.

도형은 파랑·회색, 용수철은 회색, 그래프·선의 opacity는0.65이다. 등전위 면은 더 낮은 투명도로 내부가 보이도록 한다. 기본 빠르게·0.2배 느리게, 끝 재생·유한 범위 정지와 반복, 아래쪽 진행 영역을 제공한다. 정적인 나침반에는 프레임 조작이 없다. 원본 default와 추가 탐구 입력을 구분한다. 번개의 분기 곡선 및 3차원 면/투영은 새 벡터 표현이며 원본 그림을 옮긴 것이 아니다.

## 끝 탐색 직후 재생 경합 수정

통합 검사에서 반복을 끈 뒤 끝300으로 탐색하고60ms 뒤 재생하면 두3D 전위 모델이 멈추는 실제 경합을 발견했다. 목표 단계 desired는300이지만 worker 완료 전 표시 단계 n은이전값이라 재시작 조건에서 놓쳤다. 재생은 표시 단계와 목표 단계 모두 끝인지 확인하고0으로 재시작한다. 재시작보다 이전의 큰 단계 응답은 화면에 적용하지 않고 다음 계산 작업을 진행한다. 원본 격자·순회·시간의 수치식은 변경하지 않았다. 두 원본 계산 모델의 320px 실제 읽기 재현에서1.5초 뒤 n14로 재생을 유지했다. fixture/reading 검사도 반복 해제·끝 탐색 후60ms 재생 조건으로 강화하여 같은 경합을 계속 확인한다. 처음 검사는 반복을 켜고 더 기다렸기 때문에 이 문제를 확인하지 못했다.

## 계산 중 경계 입력의 표시 장 보존

이전 계산이 진행 중이어도 경계 이벤트는 사용자가 실제로 보는 장에서 시작해야 한다. 입력 이벤트 때 표시된 Float64 장·기존 매개변수·계산 단계/완화 횟수를 독립 snapshot으로 저장해35ms debounce 후 change 요청에 전달한다. worker는 해당 장과 매개변수를 먼저 복구한 뒤 경계를 바꾼다. 따라서 이전 계산이 더 진행되었거나 다른 변경이 먼저 처리되어도 새 입력 기준 장을 바꾸지 않는다. snapshot은 입력 이벤트에만 생성하고 재생 단계에서는 추가 생성하지 않는다. 원본 가장 큰 격자는 약168KB이며 기존 SVG/수치 업데이트는 유지한다. 새 unit 회귀는 worker를3단계에서100단계로 앞서 진행한 뒤3단계 snapshot으로 연속 두 경계를 바꾸며 내부 전위가 표시했던 값에서 시작하는지 두3D 모델에 대해 확인한다. 현재 unit9/9을 통과했다.

3D 경계 값을 바꿀 때 원본의 pass=0을 보존하고, iso/단면 같은 표시 입력은 이전 완화 횟수를 그대로 유지한다. 경계 변경 뒤100으로 되돌리던 표시는 수정했다. 원본 핸들러의 pass 초기화12개 수치 확인을 source 보고서에 추가했다.

## 서로 다른 입력의 빠른 연속 변경

공통 debounce에서 마지막 key만 남기면 left0 다음 iso3을35ms 안에 바꾸었을 때 슬라이더는left0이지만 실제 경계 전위는10으로 남는 문제를 실제 교재에서 재현했다. 짧은 입력 묶음은 모든 key/매개변수 변경을 순서대로 저장하고 하나의 표시 장 snapshot에서 차례로 적용한다. 이전 요청이 아직 표시되지 않은 경우에는 baseline 매개변수와 최신 입력의 물리 경계 차이를 먼저 반영한다. 표시 옵션은 대기 입력 묶음을 즉시 처리하며 처음 상태 버튼은 대기 debounce를 취소한다. 물리→표시·표시→물리·물리→물리104개 key 조합과 이전 물리 값이 포함된 나중 표시 입력4개를 worker 회귀로 확인했다. 세 화면 너비의 실제 fixture에서도 빠른 두 입력 뒤 전체 장이 순차 이벤트 결과와 같은지 검사한다. 이는 해당 큐 의미108회귀이며 모든 원본 연속 입력 조합의 런타임 동등성을 뜻하지 않는다.
